Internal planning roadmap, reviewed 2026-08-19

Catalog PIM / DAM foundations

The existing versioned EAV core is a sound PIM kernel: typed values, immutable history, version-pinned schemas, mixins, relationships, contextual overrides, and rebuildable projections. This roadmap identifies the missing primitives needed to support a full PIM/DAM without later structural rewrites.

Design rule: add durable domain primitives before building product workflows on top of them. Context is a named catalogue scope with one parent and deterministic ancestor fallback; solve that hierarchy and assets/renditions before deep investment in channel publishing, localization, or media UI.

Foundation: add before broad adoption

P0

Tenant and identity boundary

Introduce workspace/tenant ownership for every aggregate, plus principals and authorization scopes.

Required for isolation, ownership, auditability, and any multi-team or external integration use.

Implemented

Context hierarchy and fallback

Contexts now have parent_id, a persisted default root, and one deterministic inheritance path. The seeded catalog models default → PL → PL-b2c → PL-b2c-web.

Resolved scalar reads use nearest-ancestor wins and return the supplying context, so consumers can distinguish overrides from inheritance.

P0

Audit and provenance envelope

Attach actor, source system, import job, idempotency/correlation key, reason, and effective timestamps to each mutation.

Current immutable value history captures when and what, but not who or why.

P0

Entity lifecycle and channel publication approval

Model draft, approved, published, archived, effective dates, and channel publication separately from value history.

Append-only facts do not define the exact approved state that a channel is allowed to consume.

PIM primitives

P1

Attribute constraints and cardinality

Schema-declare requiredness, uniqueness scope, min/max, pattern, precision, allowed options, and relationship cardinality. Support ordered multi-value scalar collections.

P1

Domain value types

Add rich text, enum/option, measurement plus unit, money, URL, JSON/object, and asset reference. Keep the type system extensible.

P1

Relationship semantics

Add edge order, edge metadata, inverses, target cardinality, and hierarchy/tree semantics while retaining contextual history. Define whether child scopes replace or incrementally inherit relationship sets.

P1

Business identifiers

Support schema-declared external IDs such as SKU, GTIN, supplier ID, and uniqueness policies. UUID remains internal identity.

P1

Reference data

Make option sets, controlled vocabularies, units, taxonomies, and classifications first-class versioned definitions.

P2

Validation and computed values

Add a completeness/rule engine per context and channel, then computed attributes with dependency tracking and rollups.

Implemented baseline

Entity schema migration

A validated, explicit entity migration process between blueprint revisions is available, including projection rebuild and migration reporting. Future work can expand migration transforms and richer reporting.

DAM primitives

P0 if DAM is a target

Asset aggregate and blob storage

Store immutable original identity, object-storage locator, checksum, MIME type, byte size, dimensions/duration, and ingestion state. Do not represent media as only a URL or generic entity.

P1

Asset versions and renditions

Model original files, revisions, transformations, thumbnails, crops, transcoding, focal points, and channel-specific rendition selection.

P1

Asset usage edges

Attach assets with role, order, context, crop/focal-point metadata, and usage state. This depends on relationship edge metadata and ordering.

P1

Extraction and enrichment

Capture EXIF/IPTC/XMP, OCR/transcripts, technical metadata, generated labels, and the source/confidence of machine-generated metadata.

P1

Rights and retention

Model copyright, licenses, territories, expiry, embargoes, consent/releases, restrictions, deletion, and retention policy.

P1

Processing jobs

Provide upload/download contracts, deduplication, malware scanning, extraction and transform jobs, retries, and observable status.

Platform and integration primitives

P1

Declarative projections

Version named projections independently, rebuild them from canonical facts, and provide repair/backfill operations.

P1

Context-aware query DSL

Implement typed filters, sort, facets, full-text indexing, relation-aware filters, and explicit context selection/resolution.

P1

Bulk import/export jobs

Build staging, field mapping, validation reports, dry runs, idempotency, partial-failure policy, and source attribution into the engine.

P1

Outbox and change feed

Emit ordered domain events and reliable webhook/change-feed delivery for commerce, ERP, search, and media processing integrations.

P1

Client concurrency contract

Add optimistic revision/ETag checks and command idempotency. Database locks protect storage invariants but do not prevent client-side lost updates.

Context hierarchy implementation notes

Implemented

One parent, named scopes

attribute_contexts.parent_id models a rooted tree. default is the protected sole root; every other scope has one parent and a stable human-readable code.

Implemented

Nearest ancestor wins

Resolved scalar reads try the requested scope first and then each ancestor through default. Attributes with fallback disabled do not inherit.

Implemented

Protect inherited behavior

Reparenting rejects cycles. Deletion rejects contexts with descendants or current values. Parent-change audit metadata remains part of the audit/provenance foundation.

Implemented

Expose the source scope

Resolved preview reads return both the requested context and the context that supplied each value, making overrides and inheritance explicit.
